# Runnable examples

These examples show application wiring: SDK configuration, handlers, consumer
options, cancellation, and (for OpenTelemetry) provider/exporter lifecycle.
Consumers run until Ctrl+C. Setup and publication are separate commands so you
can inspect queued messages, restart consumers, and observe real redelivery.
The integration tests remain responsible for automated behavior validation.
Consumer entrypoints do not import repository-internal helpers: their SDK setup,
handler and lifecycle can be copied into an application and adapted directly.

All commands below run from the repository root. Install Go 1.25+ and Docker
with Compose v2. No AWS account, AWS CLI, profiles, or license key is needed.

## Start and provision

```sh
docker compose up -d
go run ./examples/setup
```

Setup is safe to repeat. It creates these stable resources without deleting
pending messages:

| Resource | Purpose |
| --- | --- |
| `example-orders` | Basic SQS consumer |
| `example-sns` | SNS envelopes |
| `example-sns-raw` | SNS raw delivery |
| `example-otel` | OpenTelemetry consumer |
| `example-events` | Topic subscribed to both SNS example queues |

An SNS publish sends to both subscriptions, even when only one consumer is
running. The other queue retains its copy until consumed or explicitly removed.
Do not run multiple examples against the same queue unless you intend competing
consumers. In particular, keep the OTel consumer on its own queue.

## Consume and publish

Terminal 1:

```sh
go run ./examples/basic
```

Terminal 2:

```sh
go run ./examples/publish -target sqs
```

The publisher sends three generated JSON orders and exits. The consumer prints
processed IDs, acknowledges successful work, and continues waiting. Ctrl+C stops
polling and drains acknowledgements, preserving resources and pending messages.
Start it again to consume anything published while it was stopped.
The examples use a five-second visibility timeout for short local handlers.
An interrupted receive can leave a message temporarily invisible; after that
window it becomes eligible for redelivery. Processing must be idempotent.

| Consumer | Publisher |
| --- | --- |
| `go run ./examples/basic` | `go run ./examples/publish -target sqs` |
| `go run ./examples/sns` | `go run ./examples/publish -target sns` |
| `go run ./examples/sns -raw` | `go run ./examples/publish -target sns` |
| `go run ./examples/opentelemetry` (requires OTLP receiver) | `go run ./examples/publish -target otel -action cycle` |

Continuous traffic is generated by the publisher, not by the consumer:

```sh
go run ./examples/publish -target otel -action cycle -count 0 -interval 500ms
```

Ctrl+C stops publication. `-count` controls finite batches; `-body` accepts a
custom payload, for example:

```sh
go run ./examples/publish -target sqs -count 1 -body '{"id":"my-order"}'
```

See [basic](basic/README.md), [SNS](sns/README.md), and
[OpenTelemetry](opentelemetry/README.md) for the code and complete recipes.

## Clean up

Stop consumers and publishers before removing resources:

```sh
go run ./examples/setup -cleanup
docker compose down
```

Cleanup is safe to repeat and deletes only the named playground resources,
including their queued messages and the topic's subscriptions. It does not
reset MiniStack or remove integration-test resources. Stopping MiniStack clears
its in-memory state; setup must be rerun after recreating the container.

## Local configuration

`SQS_TEST_ENDPOINT` defaults to `http://localhost:4566` for every command. All
clients explicitly use region `us-east-1` and fake `test/test` credentials. For
AWS, replace the explicit local configuration with the SDK's default chain.
Consumers also accept `-queue` to select an existing queue; they do not create it.
The publisher targets the standard named resources.

For a host-port conflict, change the Compose mapping to
`127.0.0.1:14566:4566` and set `SQS_TEST_ENDPOINT=http://localhost:14566` for setup,
publication, consumption, and cleanup. Setup waits up to 30 seconds for SQS and
SNS. Publishers targeting SQS/OTel require only SQS; consumers report discovery
errors immediately. Run setup before starting them.
